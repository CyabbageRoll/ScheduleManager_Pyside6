📊 Schedule Manager v3
操作マニュアル

チームのプロジェクト・タスク・チケットを一元管理するスケジュール管理ツール

アプリの概要

Schedule Manager v3 は、チームのタスク管理と日次スケジュール管理を一体化した社内向けツールです。

主な機能

  • 階層管理: Project1〜Project4 → Task → Ticket の6階層でタスクを体系化
  • ガントチャート（Main）: 誰がいつ何をするかを日単位で可視化
  • ロードマップ（Plan）: 日/週/月単位の長期スケジュール表示
  • 日次スケジュール: 15分刻みでその日の作業を記録
  • チームログ（Team）: メンバー全員の勤務状況・連絡事項を一覧表示
  • タスク依頼（Request）: 他メンバーへのタスク・チケット依頼
  • AI取込: LLM（AI）の返答からタスクを自動作成
  • 工数分析（Analyze）: 見積vs実績の比較・超過アラート
💡 データの保存場所
全データは SQLite データベース（config.ini の server_dir で指定したフォルダ）に保存されます。 共有フォルダに設置することでチーム全員が同じデータを参照できます。

起動と初期設定

起動方法

  1. src/schedule_app.py を Python で実行します
    python schedule_app.py
  2. 同フォルダの config.ini が自動的に読み込まれます
  3. メインウィンドウが表示されます（最初は Main タブが開きます）

初期設定（config.ini）

初めて使う際は ⚙ Config タブ で以下を設定してください。

設定項目説明例
username自分のログインユーザー名yamada
membersチームメンバーのユーザー名（カンマ区切り）yamada, tanaka, suzuki
server_dirDBファイルの保存先フォルダ./db（共有フォルダなら //server/share/db）
daily_task_hour1日の標準作業時間（時間）5.0
[DisplayNames]ユーザー名→画面表示名のマッピングyamada = 山田
⚠ 注意: Config タブで保存後、アプリを再起動することで設定が完全に反映されます。

📊 Main タブ（ガントチャート）

Main タブは画面を左右に分割した2ペイン構成です。

  • 左パネル: 日次スケジュール（その日の作業記録）
  • 右パネル: ガントチャート（担当チケットの進捗・作業予定）

左パネル：日次スケジュール

本日の入力フォーム

日次スケジュール上部の入力欄に、その日の勤務状況を記録します。

フィールド説明

場（勤務場所）Office / Home などから選択
安（安全確認）OK / NG から選択
残（残業）No / Yes から選択
今日その日だけ表示する連絡事項（自由記述）

✅ 自動保存: 「常時」欄はフォーカスを外すか Enter を押すと自動保存されます。他の項目は Ctrl+S で保存します。

スケジュールテーブルの操作

15分刻みの時間スロット（00:00〜23:45）が縦に並んでいます。

  1. 予定を記録したい時間帯の行をクリック（複数選択は Shift+クリック または Ctrl+クリック）
  2. ガントチャートで担当のチケットをクリック
  3. 選択スロットにチケットが割り当てられ、実績工数が自動更新されます
⚠ 注意: 割り当てられるのは自分が担当するチケットのみです。他のメンバーのチケットは割り当てられません。

Free ボタン: 選択したスロットに入力済みのチケットを消去します。

右クリックメニュー

ガントのチケット行を右クリックするとメニューが表示されます。

  • ✏ Edit — Edit タブでそのチケットを表示・編集
  • 📅 開始可能日変更 — カレンダーで開始可能日を設定
  • 🏁 納期変更 — カレンダーで納期を設定
  • ☐ ToDo / ✓ Done / ✗ Cancel / ↻ Regularly — ステータス変更
  • 🗑 Delete — チケットを削除（確認ダイアログあり）
  • 📨 Request — 他メンバーへ依頼（Request タブへ移動）
💡 自分のチケットと他人のチケット
自分が担当するチケットはすべてのメニューが表示されます。他人のチケットでは 📨 Request のみ表示されます。
✅ 作業予定日の計算について
🔨 の作業予定日はシステムが自動で計算します（EDF: Earliest Deadline First アルゴリズム）。 見積工数・実績工数・開始可能日・納期をもとに、1日の標準作業時間内で無理のない順序に並べます。 納期が設定されていないチケットには、親 Task の納期から逆算した仮納期が使われます。

優先順位（priority）について

各アイテムには「順番」として優先順位が割り振られます。数字が小さいほど優先度が高く、ガントチャートの作業順序に影響します。

  • テーブル上の ▲ / ▼ ボタンで隣接行と優先順位を入れ替えられます（複数選択可）
  • アイテムを追加すると、自動的に末尾の順番が割り振られます
  • 削除・追加操作後は、1から連番になるよう自動的に整理されます

保存のしくみ（遅延保存）

Edit タブでの変更は すぐにはDBへ書き込まれません。Ctrl+S（または「💾 保存」ボタン）を押したときに初めて保存されます。

⚠ 未保存の変更がある場合
テーブル上部に「⚠ 未保存の変更があります」と表示されます。 アプリを閉じる前・Ctrl+R（再読み込み）を実行する前に必ず Ctrl+S で保存してください。
💡 再読み込みするとどうなる？
Ctrl+R（読込）を実行すると、保存していない変更はすべて破棄され、DBの最新データで上書きされます。 保存し忘れに注意してください。

📨 Request タブ（タスク依頼）

自分が担当するアイテムを他のメンバーに依頼したり、受け取った依頼を承諾・拒否します。

💡 未処理の依頼がある場合
Request タブのボタンが赤背景に変わり、未処理件数が表示されます。 タブ切替時・起動時に自動更新されます。

依頼を送る

対象の種別と動作の違い

対象の種別動作送り先の選択
Ticket対象チケットのコピーを送り先に作成（担当者を送り先に変更）複数人に同時送信可能
Task / Project1〜4そのアイテムの担当者を送り先に変更1名のみ選択可

依頼の手順

  1. 「対象」ドロップダウンから依頼したいアイテムを選択
    （[P1] 大プロジェクト / [Task] 作業名 / [Tkt] チケット名 の形式で表示されます）
  2. 種別に応じた動作説明が表示されます（Ticket: コピー作成 / Task以上: 担当者変更）
  3. 「送り先」から依頼先メンバーにチェックを入れる
  4. 「メッセージ」に一言コメントを記入（任意）
  5. 「依頼送信」ボタンをクリック
💡 ガント・Plan・Edit ツリーからも依頼可能
ガント・Plan・Edit ツリーのアイテムを右クリック → 📨 Request を選ぶと、 そのアイテムが自動選択された状態で Request タブが開きます。

受信一覧の見かた

受信一覧テーブルには以下の列が表示されます。

P1 / P2 / P3 / P4 / Task依頼対象の親階層タイトル（対象より下位の列はグレーアウト）

💡 閲覧と操作の違い
ツールバー2行目で表示メンバーを切り替えると、そのメンバーの受信一覧を閲覧できます。 ただし承諾・拒否の操作は自分（ログインユーザー）宛の依頼のみ可能です。

承諾・拒否の手順

  1. 受信一覧から処理する依頼を選択（Ctrl+クリックやShift+クリックで複数選択可）
  2. ✅ 承諾をクリック → 一括で承諾。アイテムの担当者が自分に変更されます
  3. ❌ 拒否をクリック → 依頼を却下（アイテムは変更されません）
⚠ 注意事項
  • 一度承諾した依頼は拒否できません
  • 承諾・拒否から10日経過した依頼は受信一覧から自動的に消えます（データは保持されます）

🤖 AI取込タブ

LLM（AI）にタスク整理を依頼し、その回答をそのまま取り込んでアイテムを自動作成する機能です。

使い方の流れ

① 指示メッセージ取得
→
② AI（ChatGPT等）に貼り付け
→
③ AI返答を貼り付け
→
④ 取り込みボタン
→
⑤ Edit で確認
  1. 📋 指示メッセージ取得 ボタンをクリック
    テンプレート（指示内容）＋ 既存プロジェクト一覧がクリップボードにコピーされます
  2. ChatGPT / Claude などの AI チャットを開き、コピーした内容を貼り付けて送信
    その後に整理してほしいメール・指示文なども合わせて貼り付けてください
  3. AI の返答をコピーして、AI取込タブのテキストエリアに貼り付ける
    ```items ... ``` の形式を含む回答を認識します
  4. 📥 取り込み ボタンをクリック
    内容を解析して確認ダイアログが表示されます。「OK」で DB に登録されます
  5. 自動的に Edit タブに切り替わり、取り込まれたアイテムが選択表示されます
    次へ → ボタンで取り込まれた各アイテムを順番に確認できます
💡 AI返答のフォーマット
AI にはあらかじめフォーマットが指定されています。以下の形式で返答してもらいます： 
```items
title: タスクタイトル
parent_idx: 親アイテムのIDX（0=ルート）
node_type: task または ticket
assigned_to: 担当者のユーザー名
deadline: YYYY-MM-DD
memo: メモ
---
title: 2つ目のアイテム
...
```
⚠ 注意: 取り込み後は内容を Edit タブで確認し、担当者・納期・優先順位を適切に調整してください。 取り込んだ内容は必ず Ctrl+S で保存してください。

📝 Memo タブ（メモ）

個人用の自由メモ帳です。他のメンバーには見えません。

  • 自由にテキストを記入し、「保存」ボタンでDBに保存
  • 次回起動時も内容は保持されます

階層構造（ノード種別）

アプリでは以下の6階層でデータを管理します。

[P1] 大プロジェクト
  └── [P2] サブプロジェクト
        └── [P3] フェーズ・カテゴリ
              └── [P4] 詳細区分
                    └── [Task] 作業のまとまり
                          └── [Ticket] 個別チケット ← 実際の作業単位
  • Ticket が最小単位: 日次スケジュールへの割り当て・見積工数・実績工数は Ticket に紐付きます
  • Task より上の階層: 主に分類・グルーピングのために使用。Ticket の工数は上位に積み上げられます
  • 使わない階層は省略できます（例: P1 直下に Task を置くことも可能）
  • Request は Ticket に限らず P1〜Ticket のすべての階層に対して送れます

Tips & よくある質問

Q. データの保存はいつ行われますか？

常時メモ以外の変更は自動保存されません。Ctrl+S または「💾 保存」ボタンで明示的に保存してください。 Edit タブで変更があると「⚠ 未保存の変更があります」と表示されます。 保存せずにアプリを閉じると変更が失われます。

Q. チームで共有するには？

config.ini の server_dir を共有フォルダのパス（例: //NAS/share/scheduledb）に設定し、 全メンバーが同じパスを指定することでデータを共有できます。

⚠ 同時書き込みに注意: 複数ユーザーが同時に「保存」を実行した場合、最後に保存した内容が優先されます。 Ctrl+R で定期的に最新データを読み込むことを推奨します。

Q. ガントに自分のチケットが表示されません

  1. ステータスフィルターを確認（「Todo」以外のステータスは非表示になります。「全て」を選択してみてください）
  2. 期間フィルターの範囲にチケットの作業予定日が含まれているか確認
  3. 担当者フィルターが正しく設定されているか確認
  4. チケットの担当者（assigned_to）が自分のユーザー名になっているか Edit タブで確認

Q. 作業予定日（🔨）が表示されません

作業予定日の表示には以下の条件が必要です。

  • チケットのステータスが Todo（Done/Cancel/Regularly は非表示）
  • 見積工数が 0 より大きい
  • 担当者が設定されている

Q. 納期を超過した場合はどうなりますか？

作業予定日（🔨）が納期を超えた場合、そのセルが赤で強調表示されます。 該当チケットの見積工数を確認し、優先順位を上げるか納期を調整してください。

Q. Regularly（定期）ステータスはいつ使いますか？

毎日の朝礼、週次ミーティングなど、定期的に繰り返す作業に使用します。 ガントのスケジュールバーは表示されませんが、項目名は一覧に残ります。

Q. Request を承諾したらどうなりますか？

対象アイテムの担当者（assigned_to）があなたのユーザー名に変更されます。 Ticket の場合は以降、自分のチケットとしてガントに表示され、日次スケジュールへの割り当てが可能になります。

Q. AI取込でうまく取り込めません

以下を確認してください。

  • AI の返答に ```items と ``` のコードブロックが含まれているか
  • title: と parent_idx: が必須項目として含まれているか
  • parent_idx に指定した IDX が既存アイテム一覧に存在するか
  • 「指示メッセージ取得」で取得したメッセージを AI に渡してから依頼しているか

Q. Edit で編集した内容が消えました

Ctrl+R（読込）を実行すると、保存前の変更は破棄されます。 また、他のメンバーが同じデータを上書き保存した場合も、次回の読込時に上書きされます。 重要な変更をしたらすぐに Ctrl+S で保存する習慣をつけてください。
