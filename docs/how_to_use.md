## 1. 初回セットアップ

### 1.1 Python 環境の準備

Python 3.10 以上が必要です。
プロジェクトフォルダ内に仮想環境（venv）を作成し、必要パッケージをインストールします。

```bash
# プロジェクトルートに移動
cd /path/to/a04_Schedule_Manager_v3

# 仮想環境の作成
python -m venv .venv

# 仮想環境の有効化（Windows）
.venv\Scripts\activate

# 仮想環境の有効化（macOS / Linux）
source .venv/bin/activate

# 必要パッケージのインストール
pip install PySide6 pandas openpyxl
```

### 1.2 ディレクトリ構成

```
a04_Schedule_Manager_v3/
├── .venv/              ← 仮想環境（上記で作成）
├── src/
│   ├── main.py         ← エントリポイント
│   ├── db.py           ← データベース処理
│   ├── logic.py        ← スケジューリング・検索ロジック
│   ├── ui_main.py      ← メイン画面
│   ├── ui_sub.py       ← サブ画面群
│   ├── ui_widgets.py   ← 共通ウィジェット
│   ├── config.ini      ← 設定ファイル ← ここを編集する
│   ├── db/             ← DBファイル格納先（自動作成）
│   └── logs/           ← ログファイル格納先（自動作成）
└── docs/
    └── how_to_use.md   ← このファイル
```

## 2. 起動方法

`src/` フォルダ内から `main.py` を実行します。

```bash
# src ディレクトリに移動
cd /path/to/a04_Schedule_Manager_v3/src

# 起動（仮想環境が有効化されている場合）
python main.py

# 起動（仮想環境のパスを直接指定する場合）
/path/to/a04_Schedule_Manager_v3/.venv/bin/python main.py
```

> **Windows の場合：**
> ```bat
> .venv\Scripts\python.exe src\main.py
> ```

起動すると以下の処理が自動で行われます。

1. `config.ini` を読み込み
2. DBファイル（`db/schedule.sqlite`）が存在しない場合は自動作成
3. メイン画面が表示される

## 3. config.ini の設定

`src/config.ini` をテキストエディタで編集します。**起動前に必ず自分のユーザー名を設定してください。**

```ini
[Database]
# DBファイルの格納ディレクトリ
# チームで共有する場合はファイルサーバーのパスを指定
server_dir = ./db
# 例（Windows ファイルサーバー）: server_dir = \\server\share\schedule_db
# 例（macOS / Linux NFS）:        server_dir = /mnt/fileserver/schedule_db

[User]
# 自分のユーザー名（必ず設定）
username = Yamada

# チームメンバー全員をカンマ区切りで記載
members = Yamada, Tanaka, Suzuki

[GUI]
window_width = 1500
window_height = 900
font_size = 9

[Schedule]
# タイムラインの表示開始・終了時刻（0〜23 の整数）
daily_begin_time = 6
daily_end_time = 21
# 1日の最大作業時間（スケジューリングに使用）
daily_task_hour = 5
# 休日の曜日（SUN=日, MON=月, TUE=火, WED=水, THU=木, FRI=金, SAT=土）
holidays = SUN,SAT

[DailyInfoCombo]
# チームログの選択肢（カンマ区切りで自由に変更可）
health_status = Good, Bad
work_place = Office, Home, Remote
safety = OK, NG
overwork = No, Yes

[Commands]
# カスタムコマンドボタン（ツールバーに追加）
command_01_label = レポート生成
command_01_script = scripts/report.py
```

### チーム共有 DB の設定

チームで同じDBを使う場合は、全員の `config.ini` の `server_dir` に **同じファイルサーバーのパス** を設定します。DBファイルはWALモードで動作するため、複数人の同時アクセスに対応しています。

## 5. メイン画面（タスク管理）

メイン画面は **左ペイン（ツリー）**・**中央ペイン（テーブル）**・**右ペイン（詳細）** の3分割構成です。ペインの境界をドラッグして幅を調整できます。

### 5.1 階層構造

タスクは以下の6階層で管理します。

```
Project1（最上位区分）例：経営企画部
  └─ Project2（中区分）   例：2026年度上期計画
       └─ Project3（小区分）  例：新規顧客開拓
            └─ Project4（最小PJ） 例：A社案件
                 └─ Task（作業グループ）  例：A社調査報告書
                      └─ Ticket（実作業単位）例：Web情報調査
```

### 5.2 左ペイン — 階層ツリー

| 操作 | 内容 |
|------|------|
| クリック | ノードを選択。中央ペインに子一覧を表示 |
| 「新規」ボタン | 選択ノードの子を作成（ダイアログが開く） |
| 「削除」ボタン | 選択ノードを論理削除（子がある場合・実績工数>0 の場合は不可） |
| ツリーを展開 | 三角アイコンをクリックして子を展開 |

> **自動生成チケット：** Project1〜Task を作成すると、「詳細作成」「完了」の2チケットが自動生成されます。

### 5.3 中央ペイン — 子一覧テーブル

左ペインで選択したノードの直下の子が一覧表示されます。

| 操作 | 内容 |
|------|------|
| ダブルクリック | ノード編集ダイアログを開く |
| 「追加」ボタン | 子ノードを新規作成 |
| 「編集」ボタン | 選択行を編集（ダブルクリックと同じ） |
| 「削除」ボタン | 選択行を論理削除 |
| 「↑」「↓」ボタン | 優先度（表示順）を1つ上下に変更 |

**ノード編集ダイアログの主なフィールド：**

| フィールド | 説明 |
|-----------|------|
| タイトル | ノード名（必須） |
| ステータス | todo / done / cancel / regularly |
| 優先度 | 1〜99（小さい数値 = 高優先） |
| 担当者 | メンバーから選択 |
| 見積工数(h) | 見積もり作業時間 |
| 開始可能日 | 作業を開始できる最早日 |
| 納期 | 完了すべき日 |
| カラー | ガントチャート等での表示色 |
| メモ | 備考・URLリンクの貼り付け |

### 5.4 右ペイン — 詳細・日次スケジュール

中央ペインでチケットを選択すると、右ペインにそのチケットの詳細情報と15分刻みタイムラインが表示されます（詳細は [6. 日次スケジュール](#6-日次スケジュール) を参照）。

### 5.5 ステータス変更ルール

| ルール | 内容 |
|--------|------|
| 「完了」チケットを done にする | 親ノードも自動的に done に変更される |
| 子がある親を done にしたい | 先に全ての子チケットを done / cancel にする |
| 実績工数 > 0 のノードを削除したい | 削除不可（先に日次スケジュールから割り当てを外す） |
| 削除したノードを復旧したい | 現バージョンではDB直接編集が必要（status='deleted' → 'todo'） |

## 6. 日次スケジュール

右ペイン下部に**15分刻みのタイムライン**が表示されます。チケットの作業時間を記録します。

### 6.1 スロットの割り当て

1. 中央ペインで割り当てたいチケットを選択
2. 右ペインのタイムライン上でスロットをクリック（そのスロットにチケットが割り当てられる）
3. 複数スロットを連続して割り当てる場合は1スロットずつクリック

### 6.2 割り当ての解除

解除したいスロットを選択した状態で「**Free**」ボタンをクリックします。

### 6.3 勤務時間の自動計算

スロットを割り当てると以下が自動計算され、保存時にDBに記録されます。

| 項目 | 内容 |
|------|------|
| 総実働時間 | 割り当てスロット数 × 0.25h |
| 勤務開始 | 最初に割り当てのあったスロット |
| 勤務終了 | 最後に割り当てのあったスロットの次 |
| 休憩時間 | 勤務開始〜終了間の空スロット時間 |

### 6.4 実績工数の自動集計

チケットへの割り当てスロット数に応じて、そのチケットの `actual_hours` が自動更新されます。また、親ノード（Task / Project）の `actual_hours` も配下の合算で更新されます。

### 6.5 ツールバーの日付選択

ツールバー左の「📅 日付」ボタンをクリックするとカレンダーが開き、表示日付を変更できます。過去の記録も参照できます。

> **注意：** 他のメンバーの日次スケジュールは閲覧のみです。ツールバーの「表示メンバー」で切り替えて確認できます。

## 7. ガントチャート画面

`Ctrl+2` または「📊 ガント」ボタンで開きます。

### 機能概要

- 選択したタスク配下のチケットを、**EDF（最早納期順） + 優先度**で自動並び替えて表示します
- 納期が未設定のチケットは、下流チケットの納期・見積工数から自動逆算して仮設定されます

### 使い方

1. 上部のコンボボックスから確認したい **Task** を選択
2. チケットが納期順・優先度順に並び替えられて表示される
3. 各チケットの推奨実施順を確認する

## 8. ロードマップ画面

`Ctrl+3` または「🗺 ロードマップ」ボタンで開きます。

Project1〜Task の `start_available`（開始可能日）〜 `deadline`（納期）を帯グラフで表示し、プロジェクト全体の期間を俯瞰できます。

- 階層はインデントで表現されます
- 帯の色はノードの `カラー` フィールドに対応します

## 9. 分析画面

`Ctrl+4` または「📈 分析」ボタンで開きます。

### 表示内容

| テーブル | 内容 |
|---------|------|
| 担当別工数 | メンバーごとの見積・実績工数の合計 |
| PJ別工数 | Project1別の見積・実績工数の合計 |
| 予算超過チケット | 実績工数が見積工数を超えているチケット一覧 |

### 期間フィルター

「開始日」「終了日」を指定してデータを絞り込みます。空欄にすると全期間が対象になります。

## 10. 検索画面

`Ctrl+5` または「🔍 検索」ボタンで開きます。

### 検索条件

| 条件 | 説明 |
|------|------|
| キーワード | タイトル・メモを対象に部分一致検索 |
| 担当者 | 特定メンバーのノードのみ表示 |
| ステータス | 複数チェックボックスで選択 |
| 更新日（From〜To） | 最終更新日の範囲でフィルター |

### プリセット

「**今週の仕事**」ボタンをクリックすると、今週（月曜〜今日）更新されたチケットが自動的に抽出されます。週次報告のまとめに便利です。

### エクスポート

検索結果を以下の形式でエクスポートできます。

- **CSV エクスポート**：`UTF-8 BOM` 形式で保存（Excelで直接開ける）
- **Excel エクスポート**：`.xlsx` 形式で保存

## 14. LLM連携テキスト一括入力

メイン画面の中央ペイン下部に「**テキスト一括入力（LLM連携）**」エリアがあります。LLMが出力したテキストをコピー＆ペーストするだけで、複数チケットを一括作成できます。

### 入力フォーマット

```
# コメント行（#で始まる行は無視されます）
タイトル, 優先度, 見積工数(h), 開始可能日, 納期, ステータス, メモ
```

| 位置 | フィールド | 必須 | デフォルト | 説明 |
|------|-----------|------|-----------|------|
| 1 | タイトル | ○ | — | チケット名 |
| 2 | 優先度 | — | 99 | 整数（1〜99、1が最優先） |
| 3 | 見積工数(h) | — | 0.25 | 小数可（例：1.5） |
| 4 | 開始可能日 | — | 空欄 | YYYY-MM-DD 形式 |
| 5 | 納期 | — | 空欄 | YYYY-MM-DD 形式 |
| 6 | ステータス | — | todo | `todo` または `regularly` |
| 7 | メモ | — | 空欄 | 自由テキスト |

### 入力例

```
# Task: A社調査報告書 のチケット一覧
A社Web情報調査, 1, 3.0, 2026-04-01, 2026-04-10, todo, 公式サイト・プレスリリース調査
実地調査計画作成, 2, 2.0, , 2026-04-12, todo,
報告書ドラフト作成, 3, 8.0, , 2026-04-25, todo, 初稿のみでOK
週次進捗報告, 10, 0.5, , , regularly, 毎週月曜
```

### LLMへのプロンプト例

> 以下のタスク「A社調査報告書」を遂行するためのチケット一覧を作成してください。
> フォーマット：`タイトル, 優先度, 見積工数(h), 開始可能日, 納期, ステータス, メモ`
> 優先度は1（最優先）〜99。日付はYYYY-MM-DD形式。コメント行は#で始める。

### 使い方

1. 左ペインのツリーでチケットを追加したい **Task** を選択
2. テキストエリアにフォーマットに沿ったテキストを貼り付け
3. 「**一括作成**」ボタンをクリック
4. 作成結果（成功件数・エラー内容）がメッセージで表示される

## 15. 保存と読み込み

### 保存（Ctrl+S）

ツールバーの「**💾 保存**」ボタンまたは `Ctrl+S` で、変更データをDBに書き込みます。

- 保存対象は**自分のデータのみ**（他のメンバーのデータは変更不可）
- 対象は直近2日以内に更新されたレコード

> **こまめに保存することを推奨します。**

### 読み込み（Ctrl+R）

ツールバーの「**🔄 読込**」ボタンまたは `Ctrl+R` で、DBから最新データを読み込んで画面を更新します。

- 他のメンバーが追加・変更したデータを取り込む際に使用
- 自分の未保存の変更は上書きされるので注意

## 17. ログファイル

アプリの動作ログは `src/logs/` フォルダに日付別で保存されます。

```
src/logs/
└── app_2026-03-16.log
```

## 18. トラブルシューティング

### 起動できない

**症状：** `ModuleNotFoundError: No module named 'PySide6'`
**対処：** 仮想環境が有効になっているか確認し、パッケージをインストールしてください。
```bash
pip install PySide6 pandas openpyxl
```

---

**症状：** `DB 初期化に失敗しました`
**対処：** `config.ini` の `server_dir` に指定したパスが存在するか、書き込み権限があるか確認してください。

---

**症状：** 画面が真っ白になる / 一部が表示されない

### データが消えた・表示されない

**症状：** 保存したはずのデータが表示されない
**対処：** `Ctrl+S` で保存後 `Ctrl+R` で再読み込みしてください。

---

**症状：** チームメンバーのデータが表示されない
**対処：**
1. `config.ini` の `members` に全員が正しく記載されているか確認する
2. `Ctrl+R` で最新データを読み込む
3. ツールバーの「表示メンバー」で該当メンバーを選択する

---

### ノードが削除できない

**症状：** 削除ボタンを押してもエラーが出る
**対処：**
- 子ノードが存在する → 先に子ノードをすべて削除または `cancel` にする
- 実績工数 > 0 → 日次スケジュールの割り当てをすべて解除してから再試行

---

### その他

バグを発見した場合は、アプリ内の「ℹ バージョン」画面のバグレポート欄から報告するか、`src/logs/` のログファイルを添えて担当者に連絡してください。
