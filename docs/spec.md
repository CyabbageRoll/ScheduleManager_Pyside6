## 1. システム概要

チーム内での作業管理・スケジューリング・工数記録を統合的に行うデスクトップアプリケーション。Project1〜4・Task・Ticketの6階層でタスクを管理し、日次の作業記録から工数分析・ガントチャートまでを一貫して扱う。

### 1.1 基本方針

| 項目 | 内容 |
|------|------|
| 言語 | Python |
| UIフレームワーク | **PySide6** |
| データベース | SQLite（ファイルサーバー上に配置、チーム共有） |
| 認証 | 不要（ファイルサーバーのOS権限で管理） |
| 他ユーザーデータ | 閲覧可 ／ 編集不可 |
| テーマ | ライト固定 |

### 1.2 主な機能一覧

- 6階層（Project1〜4 / Task / Ticket）によるタスク管理
- 日次スケジュール計画・実績記録（15分刻みタイムライン）
- EDF＋優先度ベースの自動スケジューリング（ガントチャート）
- ロードマップ表示（Task以上の帯グラフ）
- 工数集計・分析（担当別・PJ別・見積vs実績等）
- チーム間のタスク依頼・承諾ワークフロー
- チーム日次ログ（健康状態・連絡事項）
- キーワード・条件複合検索
- CSV/Excelエクスポート
- LLM連携用テキスト一括チケット作成
- カスタムコマンドボタン（管理者設定）
- メモ機能（ユーザーごとの自由テキスト）
- バージョン・バグレポート機能

## 2. 階層構造

### 2.1 階層定義

| 階層レベル | 名称 | 概要 | 備考 |
|-----------|------|------|------|
| Level 1 | Project1 | 最上位区分 | 例：部門・事業単位 |
| Level 2 | Project2 | 中区分 | 例：フェーズ・大テーマ |
| Level 3 | Project3 | 小区分 | 例：機能グループ |
| Level 4 | Project4 | 最小プロジェクト | 例：個別案件 |
| Level 5 | Task | 作業グループ | 例：A社調査報告書 |
| Level 6 | Ticket | 実作業単位 | 例：Web調査・実地調査計画作成 |

**例：**
- Project1：経営企画部
- Project2：2026年度 上期計画
- Project3：新規顧客開拓
- Project4：A社案件
- Task：A社調査報告書
- Ticket：A社Web情報調査 ／ 実地調査計画作成 ／ 報告書ドラフト作成

### 2.2 親子自動生成ルール

- 親ノード（Project1〜4・Task）を作成すると、子ノードに **「詳細作成」「完了」の2チケットが自動生成**される
- 「完了」チケットのステータスを `done` に変更すると、**親ノードも自動的に `done` に変更**される
- 子ノードは表形式（テーブルUI）で直接入力・編集が可能

### 2.3 操作制約

- 子ノードが存在する親ノードは `done` に変更できない（子を先に完了させること）
- 親ノードが `done` のとき、子ノードを `todo` に戻すことはできない
- 実績工数（actual_hours）が0より大きいノードは削除不可
- 子ノードが存在するノードは削除不可
- 削除は**論理削除**（`status = 'deleted'`）とし、誤削除時に復旧可能とする

## 3. データフィールド定義

### 3.1 共通フィールド（全階層共通）

nodesテーブルの全フィールドを以下に示す。

| フィールド名 | 型 | 必須 | 説明 |
|------------|-----|------|------|
| IDX | TEXT | ○ | 主キー。`YYMMDD_HH + MD5[:6]` 形式のハッシュ文字列（複数クライアント同時書き込み時の衝突回避のためTEXT型） |
| node_type | TEXT | ○ | project1 / project2 / project3 / project4 / task / ticket |
| parent_id | TEXT | ○ | 親ノードのIDX（ルートは "0"） |
| title | TEXT | ○ | タイトル・名称 |
| status | TEXT | ○ | todo / done / cancel / regularly / deleted |
| priority | INTEGER | ○ | 優先度（小さい数値 = 高優先、推奨1〜99） |
| assigned_to | TEXT | ○ | 担当ユーザー名 |
| estimated_hours | REAL | △ | 見積もり工数（時間）。Ticketは必須（0より大きい値） |
| actual_hours | REAL | － | 実績工数（時間）。日次スケジュールから自動集計 |
| deadline | DATE | － | 納期（YYYY-MM-DD） |
| start_available | DATE | － | 開始可能日（YYYY-MM-DD） |
| actual_start | DATE | － | 実績開始日（YYYY-MM-DD） |
| actual_end | DATE | － | 実績完了日（YYYY-MM-DD） |
| memo | TEXT | － | メモ・備考（自由記述。URLリンクの貼り付け可） |
| color | TEXT | － | 表示色名（例：Cyan, Red, Green）。ガントチャート等で視認性向上に使用 |
| created_at | TEXT | ○ | 作成日（YYYY-MM-DD、自動設定） |
| updated_at | TEXT | ○ | 最終更新日（YYYY-MM-DD、保存時自動更新） |

> **廃止フィールド（v2から削除）：** `Request`（タスク依頼ワークフローで代替）、`Goal`（memoに統合）、`Difficulty`（priorityで代替）、`Num_Active_Children`（DBクエリで動的計算）

### 3.2 ステータス定義

| ステータス | 意味 | 備考 |
|-----------|------|------|
| todo | 未着手・進行中 | デフォルト値 |
| done | 完了 | 「完了」チケットdone→親も自動done |
| cancel | 中止・キャンセル | 工数集計から除外 |
| regularly | 定期繰り返し作業 | 会議等。親の進捗計算には含めないが工数にはカウント |
| deleted | 論理削除済み | 表示非表示。復旧可能 |

### 3.3 優先度

- 整数値で管理（小さい数値 = 高優先度）
- 推奨範囲：1〜99（1が最優先）
- 同一Taskに属するTicketは優先度順（昇順）に上流→下流の依存関係として扱う

## 4. 日次スケジュール機能

### 4.1 タイムライン方式（15分刻み）

日次スケジュールはv2と同様の**15分刻みタイムライン方式**を採用する。

- 1日を96スロット（00:00〜23:45、各15分）に分割
- 各スロットにTicketのIDXを割り当てる形式
- `daily_schedule` テーブルの列名：`C0000`, `C0015`, ..., `C2345`
- 1つのスロットに割り当てられるチケットは1つのみ（重複防止が直感的）
- 表示期間：**1日分のみ**

### 4.2 予定の作成・更新

- チケット一覧からチケットを選択し、タイムライン上のスロットをクリックまたはドラッグして割り当て
- 「Free」ボタンで選択スロットの割り当てを解除
- `regularly` ステータスのチケットは通常チケットとは分離して表示
- 他ユーザーの日次スケジュールは閲覧のみ可（編集不可）

### 4.3 実績工数の自動集計

- Ticketの `actual_hours` = 当該チケットが割り当てられたスロット数 × 0.25h
- スケジュール変更のたびに `actual_hours` を増減更新
- Task / Project の `actual_hours` は配下チケットの合算（再帰集計）
- `cancel` および `deleted` ノードは集計から除外
- `regularly` ノードの工数は親Taskの `actual_hours` に**カウントする**（進捗計算には含めない）

### 4.4 勤務時間の自動計算

タイムライン上のチケット割り当てから以下を自動計算し `daily_schedule` に保存する：

| フィールド | 内容 |
|-----------|------|
| CTOTAL | 総実働時間（スロット数 × 0.25h） |
| CFROM | 最初に割り当てのあったスロット名（例：C0900） |
| CTO | 最後に割り当てのあったスロット名の次のスロット |
| CBREAK | 割り当て開始〜終了の間の空スロット時間（休憩等） |

### 4.5 日次ログ（チーム共有情報）

各ユーザーが毎日以下を入力する（`daily_log` テーブルに格納）：

| フィールド | 内容 | 入力方式 |
|-----------|------|---------|
| health_status | 健康状態 | コンボボックス（例：Good / Bad） |
| work_place | 勤務場所 | コンボボックス（例：Office / Home） |
| safety | 安全確認 | コンボボックス |
| overwork | 残業予定 | コンボボックス |
| notes | 注意事項・連絡事項 | 自由テキスト（複数行）※Info1/Info2/Info3を統合 |

コンボボックスの選択肢は `config.ini` で設定可能。

## 5. スケジューリング・ガントチャート

### 5.1 Ticket の自動スケジューリング（EDF + 優先度）

同一Taskに属するTicket群に対して以下のロジックで実施順序を決定する。

#### 5.1.1 納期の逆算計算

- 納期が未設定のチケットは、同Task内の下流チケット（優先度が低いもの）の納期・見積工数から逆算して自動設定
- **逆算式：** 上流チケット納期 ＝ 下流チケット納期 − 下流チケット見積工数の合算（日換算）

#### 5.1.2 スケジューリングアルゴリズム

- 基本方針：**EDF（Earliest Deadline First）** — 納期が早いチケットを優先
- 同一Task内では、優先度順（数値昇順）に上流→下流の依存として順序固定
- `start_available` より前には配置しない
- 担当者の稼働時間（`daily_task_hour`）を考慮し、1日の上限工数内に収まるよう配置

### 5.2 ガントチャート表示（Ticket レベル）

- 横軸：日付、縦軸：チケット名（担当者・優先度付き）
- バー色：`color` フィールドまたはステータス別（todo=青、done=緑、cancel=灰、regularly=橙）
- 納期超過・遅延チケットは**赤でハイライト**
- チケットクリックで詳細パネルを表示

### 5.3 ロードマップ表示（Task 以上）

- Project1〜4・Taskの `start_available` 〜 `deadline` を帯グラフで表示
- 階層をインデントで表現し、親子関係を視覚的に把握
- 帯の色は `color` フィールドを使用

## 7. 工数分析機能

工数データを多角的に可視化し、チームの作業状況を把握・改善する。

### 7.1 集計軸

- 期間：日次・週次・月次・カスタム
- 対象：個人・チーム全体・特定プロジェクト
- グラフライブラリ：PySide6 + **matplotlib** または **pyqtgraph**

### 7.2 分析ビュー一覧

| ビュー名 | グラフ種別 | 内容 |
|---------|----------|------|
| 担当別工数 | 棒グラフ（週次/月次） | メンバーごとの工数比較・負荷状況確認 |
| PJ別工数内訳 | 円グラフ／積み上げ棒 | どのPJに工数が集中しているかを把握 |
| 見積 vs 実績比較 | グループ棒グラフ | チケット・タスク単位の乖離を可視化 |
| 週次工数トレンド | 折れ線グラフ | チーム全体の工数推移・繁閑把握 |
| 作業密度ヒートマップ | カレンダー型ヒートマップ | 日別の作業量を色で表現 |

## 8. チーム機能

### 8.1 タスク依頼ワークフロー

- **依頼者：** 対象チケットを選択し、担当者・メッセージを入力して依頼送信
- **受信者：** 依頼一覧から確認し「承諾」または「拒否」を選択
- **承諾時：** チケットの `assigned_to` が受信者に変更され、受信者の担当リストに追加
- **拒否時：** アプリ内メッセージで依頼者に通知
- 他ユーザーのチケット・スケジュールは**閲覧のみ可（編集不可）**
- 競合処理：ユーザーは自分のデータのみ編集可能なため基本的に競合は発生しない。工数集計は1ユーザーが1レコードを専有する設計で競合を防ぐ

### 8.2 チーム日次ログ表示

- チーム全員の当日分（勤務時間・場所・残業・健康状態・連絡事項）を表形式で一覧表示
- 朝会・日報代わりとして利用
- 過去ログの閲覧可（日付選択で参照）

## 9. データベース設計

### 9.1 構成方針

- SQLiteファイルをファイルサーバー上の共有フォルダに配置
- 複数クライアントからの同時アクセスに対応（**WALモード**使用）
- DBファイルパスは `config.ini` で指定
- ノードIDは `YYMMDD_HH + MD5[:6]` 形式のTEXT型（複数クライアント同時生成時の衝突回避）
- データ削除は論理削除（`status = 'deleted'`）を基本とする

### 9.2 テーブル一覧

| テーブル名 | 概要 | 主なカラム |
|-----------|------|-----------|
| nodes | 全階層ノード | IDX(TEXT), node_type, parent_id, title, status, priority, assigned_to, estimated_hours, actual_hours, deadline, start_available, actual_start, actual_end, memo, color, created_at, updated_at |
| users | ユーザー情報 | IDX(TEXT), username, display_name, team |
| daily_schedule | 日次15分刻みスケジュール | IDX(TEXT=date-user), Owner, C0000〜C2345（96列）, CTOTAL, CFROM, CTO, CBREAK, Last_Update |
| daily_log | 日次ログ・連絡事項 | IDX(TEXT=date-user), Owner, health_status, work_place, safety, overwork, notes, Last_Update |
| task_assignments | タスク依頼・承諾 | IDX(TEXT), ticket_id, from_user, to_user, status, message, created_at, responded_at |

## 11. LLM連携テキスト一括チケット入力

会社環境でLLMとAPIが繋がらない場合を想定し、LLMが出力したテキストを手動コピペすることでチケットを一括作成できる機能を提供する。

### 11.1 入力フォーマット仕様

```
# コメント行（#で始まる行および空行は無視）
タイトル, 優先度, 見積工数(h), 開始可能日, 納期, ステータス, メモ
```

**フィールド詳細：**

| 位置 | フィールド | 必須 | デフォルト | 説明 |
|------|-----------|------|-----------|------|
| 1 | タイトル | ○ | — | チケット名 |
| 2 | 優先度 | — | 99 | 整数（1〜99、1が最優先） |
| 3 | 見積工数(h) | — | 0.25 | 小数可（例：1.5） |
| 4 | 開始可能日 | — | 空欄 | YYYY-MM-DD 形式 |
| 5 | 納期 | — | 空欄 | YYYY-MM-DD 形式 |
| 6 | ステータス | — | todo | todo / regularly |
| 7 | メモ | — | 空欄 | 自由テキスト |

**入力例：**
```
# Task: A社調査報告書 のチケット一覧
# タイトル, 優先度, 見積工数(h), 開始可能日, 納期, ステータス, メモ
```

### 11.2 入力時のバリデーション

- 同名チケットが既存の場合は上書き確認ダイアログを表示
- 見積工数が0以下の場合はエラー表示
- 日付フォーマット不正の場合はエラー表示（その行のみスキップ）
- エラー行はテキストエリアに残し、成功行のみ作成

## 12. 設定・起動

### 12.1 設定ファイル（config.ini）

```ini
[Database]
server_dir = //server/share/schedule_db

[User]
username = UserName
members = UserName, Member2, Member3

[GUI]
window_width = 1500
window_height = 1000
font_family = Meiryo
font_size = 9

[Schedule]
daily_begin_time = 6
daily_end_time = 21
daily_task_hour = 5
holidays = SUN,SAT

[DailyInfoCombo]
health_status = Good, Bad
work_place = Office, Home
safety =
overwork =

[Commands]
command_01_label = コマンド1
command_01_script = scripts/command01.py
command_02_label = コマンド2
command_02_script = scripts/command02.py
```

### 12.2 起動時処理

1. `config.ini` を読み込み、DB接続確認
2. `username` でユーザー設定（未設定なら入力ダイアログ）
3. DBファイルが存在しない場合は初期テーブル自動作成
4. メイン画面を表示

### 12.3 保存・読み込み

- **Save（Ctrl+S）：** 変更されたデータをサーバーのSQLiteに書き込み。保存対象は `updated_at` が直近2日以内のデータ（自分のデータのみ）
- **Load（Ctrl+R）：** サーバーのSQLiteから最新データを読み込み、画面を更新

### 12.4 ログ

- ユーザーごとのデバッグログをローカルに保存（`log/debug_<username>.log`）
- エラー発生時はサーバーの `log/<username>/` にもコピー
- エラー発生時はユーザーへポップアップ通知（5分間隔でサーバーへのコピーを制限）

## 13. 技術スタック・ディレクトリ構成

### 13.1 使用ライブラリ（予定）

| ライブラリ | 用途 |
|-----------|------|
| PySide6 | UIフレームワーク |
| sqlite3（標準） | データベース |
| matplotlib / pyqtgraph | グラフ描画 |
| configparser（標準） | 設定ファイル管理 |
| pandas | データ集計・分析 |
| openpyxl または xlsxwriter | Excelエクスポート |

### 13.2 ディレクトリ構成（6ファイル構成）

LLMを使った修正時にファイルを渡しやすいよう、Pythonファイルを**6つ**に集約する。

```
schedule_app/
├── main.py           # エントリポイント・設定読み込み・ロギング・起動
├── db.py             # DB接続・スキーマ定義・CRUD・工数集計・IDX生成
├── logic.py          # スケジューリング(EDF)・タスク依頼・検索・エクスポート
├── ui_main.py        # メインウィンドウ・ツールバー・3ペイン・日次スケジュール
├── ui_sub.py         # ガントチャート・ロードマップ・分析・検索・チームログ・メモ・バージョン画面
├── ui_widgets.py     # 共通ウィジェット（日付選択・ユーザー選択・スクロールテーブル等）
├── config.ini        # 設定ファイル
└── assets/           # アイコン等リソース
```

**各ファイルの責務：**

| ファイル | 主な内容 |
|---------|---------|
| `main.py` | QApplication起動、config.ini読み込み、ロギング設定、起動ダイアログ |
| `db.py` | DB接続（WALモード）、テーブル定義・初期化、CRUD操作、IDX生成（ハッシュ）、工数集計ロジック |
| `logic.py` | EDF+優先度スケジューリング、納期逆算、タスク依頼ワークフロー、検索ロジック、CSV/Excelエクスポート |
| `ui_main.py` | QMainWindow、ツールバー、左ペイン(QTreeView)、中央ペイン(QTableView+テキスト一括入力)、右ペイン(詳細+タイムライン) |
| `ui_sub.py` | ガントチャート、ロードマップ、工数分析（グラフ）、検索画面、チームログ、タスク依頼、メモ、バージョン画面 |
| `ui_widgets.py` | 日付選択ボタン、ユーザー選択コンボ、スクロール可能テーブル、カラー選択、ボタン行、カスタムコマンドボタン |

## 14. 採用機能一覧

コメントで決定した採用・不採用の一覧。

### 採用

| 機能 | 概要 |
|------|------|
| テーブル直接編集 | セル内ダブルクリック編集、Tab/Enterでセル移動（Excelライク） |
| キーボードショートカット | Ctrl+S/R/N、F2、Ctrl+1〜8 |
| CSV/Excelエクスポート | 検索結果・工数分析結果のエクスポート |
| D&Dで順序・親変更 | 階層ツリーおよびチケット一覧でD&D操作 |
| フィルタリング設定の保持 | 最後のフィルター条件を次回起動時に復元 |
| メモ機能 | ユーザーごとの自由テキストメモ（継続） |
| バージョン・レポート機能 | バージョン情報・バグレポート（継続） |
| カスタムコマンドボタン | config.iniで定義（継続） |
| URLリンクのmemo貼り付け | ファイル添付の代わりにリンク管理 |
| LLMテキスト一括入力 | CSV形式テキストからチケット一括作成 |

### 不採用・保留

| 機能 | 理由 |
|------|------|
| 納期アラート通知 | 不要 |
| 作業タイマー機能 | ユーザーに不人気。将来的に仕様を再検討 |
| ダークモード | ライトテーマ固定 |
| ファイル添付 | 不採用。memoへのリンク貼り付けで代替 |
| メール通知連携 | 社内環境上困難 |
| 定期タスク自動生成 | 将来的にユーザーの声を聞いて検討 |
